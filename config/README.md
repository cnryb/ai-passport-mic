# 按键映射配置

`button-map.example.json` 是**可执行样例**，由 `apm-protocol` 的单测直接 `include_str!` 吃进去
（`example_file_parses`），所以它坏掉会当场红。字段已经定死，实现时按这份说明来，不要静默改名。

```json
{
  "schema": "ai-passport-mic-keymap-4",
  "bindings": {
    "up":   { "modifiers": ["ctrl"], "key": "enter" },
    "down": { "modifiers": [],       "key": "esc", "repeat": 2 },
    "ok":   { "modifiers": [],       "key": "ptt-toggle" }
  },
  "hooks": {
    "capture.start": { "modifiers": [], "key": "f5" },
    "capture.stop":  { "modifiers": [], "key": "f6" }
  }
}
```

## 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schema` | string | 固定 `ai-passport-mic-keymap-4`。版本号变了就要写迁移说明（见下） |
| `bindings` | object | 键是**事件名**，值是动作对象；未出现的事件使用默认值 |
| `bindings.*.modifiers` | string[] | `ctrl` / `shift` / `alt` / `win`（macOS 上 `win` 即 Command），空数组表示无修饰键 |
| `bindings.*.key` | string | 目标键名（小写，如 `enter` / `esc` / `a` / `f5`），或保留动作 `ptt-toggle`；修饰键本身也能作为目标键：`lalt` / `ralt`（见下） |
| `bindings.*.repeat` | number | 可选，目标键**连发次数**，缺省 1，上限 4。例：`down` + `repeat: 2` = 按一次发两记 Esc |

## 开麦键（`ptt-toggle` 绑在哪个键上）

`ptt-toggle` 是**保留动作**：按一下开麦、再按一下关麦。它绑在哪个事件上，那个事件就是
**开麦键**。约束是**整个映射里恰好一个**（不是"必须是 `ok`"）：

- 默认 `ok`（`bindings` 里不写也会补上）；
- 可以换成 `up` / `down`，例如 `{"bindings":{"up":{"key":"ptt-toggle"}}}` ——
  这时 `ok` 就是普通按键，**未绑定 = 不动作**，不会继承任何注入键；
- **0 个** → 报错 `ptt-toggle` 缺失（麦克风没有开关）；
- **2 个及以上** → 报错并把冲突的事件名都列出来（按一次会切换两遍）。

`hooks` 里禁止出现 `ptt-toggle`（见下）。

## 修饰键作为目标键（`lalt` / `ralt`）

有些软件的热键是**单按右 Alt**（不与任何键组合），这时把修饰键本身当目标键：

- `lalt` = 左 Alt / 左 Option（macOS 键码 58）；`ralt` = 右 Alt / 右 Option（macOS 键码 61）；
- 注入是**点按**（按下 + 弹起），与普通键一致；`modifiers` 里依然只能填 `alt` 这个组合
  修饰键，左右语义只在目标键 `lalt` / `ralt` 上体现；
- 仅 macOS 注入层实现（CGEvent）；Windows 侧 SendInput 未实现时同样报"平台未实现"。

## 设备屏幕上显示什么

映射会**同步到设备屏幕上**（`SET_KEY_LABELS`，`0x05`）：PC 连上设备后推一次，
之后每次保存 / 导入 / 恢复默认都再推一次；断链后设备回到内置默认文案。

屏幕上每行只有一句人话，生成规则（`apm_protocol::device_labels`）：

| 映射动作 | 屏幕上的文字 |
| --- | --- |
| `ptt-toggle`（开麦键） | `开麦 关麦`，并在键名后加 `*` |
| `ctrl+enter` | `ctrl+enter`（**键名照抄 keymap 原文，不做中文翻译**） |
| `esc` + `repeat: 2` | `esc x2` |
| 未绑定 | `无` |

两条约束：

- **不做键名翻译表。** 翻译表就是第二份真相，`config/README.md` 与它必然会漂移。
  屏幕上出现 `ctrl+enter` 时，它和这份文档里写的是同一个字符串。
- 单条上限 24 字节（UTF-8），超长在**字符边界**上截断；设备只收字库里有的字，
  PC 侧不做字符过滤（缺字形的会显示成 `?`，并在日志里留一条 WARN 打出原文）。

## 事件名（按键）

**一个键一个动作，共 3 个事件**：`up`、`down`、`ok`。没有点号、没有手势维度。
三者里恰好一个是**开麦键**（绑 `ptt-toggle`），其余两个是普通快捷键（见上）。

版本演进（每一步都是"更少、更好记"）：

| 版本 | 事件数 | 形态 |
| --- | --- | --- |
| v1 | 15 | 3 键 × 短按/双击/长按/按下/抬起 |
| v2 | 6 | 3 键 × 按下/抬起 |
| v3 | 3 | 3 键，每键一个动作 |
| **v4（当前）** | 3 + 2 钩子 | 在 v3 上加**采集状态钩子**：开麦/关麦时自动注入快捷键 |

v3 的语义：**按一次 = 一次动作**。开麦键因此从"按住说话、松手停"变成
**"按一下开、再按一下关"**（`ptt-toggle`）。三个键、三个动作，用户不用记任何手势。

**v4 没有改事件表**，只加了可选的 `hooks` 表。"开麦键可以从 `ok` 换到 `up`/`down`"
是**放宽**校验（"`ok` 必须是" → "恰好一个事件是"），所有既有 v4 文件在新规则下依然合法，
**因此不升 schema 版本**：升版本只会多出一张兼容表，买不到任何东西。

代价要说清楚：**toggle 没有"松手自动停"**。开着麦克风去接杯水，回来还在采。
所以配套必须有两件事：① 界面上一直能看到"正在采集"（**已实现**：`streaming` 状态 +
运行时长 + 实时电平表）；② 一个超时兜底（**已实现 2026-11-06**：连续采集自动关，
**默认 10 分钟**，可在界面调 1–1440 分钟，对所有推流生效），
否则忘记关麦是必然会发生的事。兜底属于 PC 端 `apm_app` 的事，见
[`../docs/GUI.md`](../docs/GUI.md) §14.19。

`repeat` 仍然保留：它描述**动作**（把这个键连发几次），不是手势。

## 采集钩子（`hooks`）

按键管的是"这个键被按下时做什么"；**钩子**管的是"开始/停止采集的那一刻做什么"。
两者是不同维度的东西，所以分开存放（按键在 `bindings`，钩子在 `hooks`）：

| 钩子 | 触发时机 |
| --- | --- |
| `capture.start` | 采集真正起来之后（`start_stream` 成功） |
| `capture.stop` | 停止采集时——包括手动停止**和链路断开导致的自动停止** |

规则：

- 动作是**点按**（按下 + 弹起），不是按住不放；
- 未配置 = 不动作，这是默认；
- **钩子里禁止 `ptt-toggle`**：开麦的瞬间再 toggle 一次，等于自己把自己关掉；
- 注入需要**辅助功能权限**（系统设置 → 隐私与安全性 → 辅助功能）。没权限时系统会
  **静默丢弃**注入的按键，应用会把它记成一条 warn 日志，不会让开麦失败。

## 兼容：只认 v3 与 v4

| schema | 处理 |
| --- | --- |
| `ai-passport-mic-keymap-4` | 当前版本，严格校验 |
| `ai-passport-mic-keymap-3` | **可读**。形态与 v4 相同，只差可选的 `hooks` 表（缺省为空），其余一字不动 |
| `ai-passport-mic-keymap-2` / `-1` | **整份拒绝**，报 `Schema` 错误并提示重新导入 |

**为什么不迁移 v1 / v2**：项目到 2026-11 为止从未发布过任何版本（无 tag、无外发包），
那两个 schema 只存在于开发期的临时文件里，没有人手上有需要迁移的真实配置。
为它们保留 `up.press` → `up` 的双状态归并、`short/double/long` 的静默丢弃，是拿
80 行代码加 3 个测试去保护一个不存在的用户群；而"按下优先还是抬起优先"这类
归并规则本身就在猜用户意图。真遇到旧文件时报错让人重新导入，比猜更诚实。

v3 文件读进来后一旦保存/导出，**落盘就是 v4**（当前版本）。

## 硬约束

1. **恰好一个事件绑 `ptt-toggle`**（开麦键）：它是麦克风唯一的开关，缺了没有开始采集的
   办法，多了按一次会切换两遍。默认是 `ok`，可以换成 `up` / `down`。
   钩子里出现 `ptt-toggle` 会被整份拒绝（同一个道理，触发时机不同）。
2. 注入快捷键时用"完整事件 + flags"一次性发出，修饰键写在事件 flags 里，不单独发修饰键
   事件，因此不存在需要事后释放的残留修饰键状态。
3. 导入时的校验顺序：`schema` 版本 → 事件名合法 → 键名/修饰键在支持列表内 → PTT 约束
   （恰好一个）。
4. 导出只写当前生效的绑定，不写注释与未知字段，保证 round-trip 稳定。
5. 写 `schema` 为 v4 的文件时出现 `up.press` / `up.release` / `*.short` 等旧写法一律**报错**
   （那是旧版写法）。只有 `schema` 本身是 v3 时才接受，且 v3 事件名同样不含点号。
6. **换开麦键时两边的绑定都不搬迁**：旧开麦键变回"未绑定 = 不动作"，
   被选中的键原有的快捷键也被清掉（同一个键不能既开关采集又注入按键）。
   界面在换的瞬间提示被清掉的具体内容。让它继承会变成"习惯性按 OK"的人
   突然开始往前台应用敲键，比什么都不做危险。

## 与固件的关系

按键的**物理判定**（消抖、按下/抬起）在固件；**映射到哪个键**在 PC 端。

固件仍然会为每个键上报 **5 种手势码**（按下 / 抬起 / 短按 / 双击 / 长按，见
`docs/ARCHITECTURE.md` 的 EVENT 帧），这是**跨端协议，v3 与 v4 都没有改它**——改协议要动
帧格式、UUID 与共享向量，收益只是省几帧通知，不值得。PC 端只消费 `PRESS`（按下那一瞬），
`RELEASE` / `CLICK` / `DOUBLE` / `LONG` 全部忽略。

注意一个副作用：**双击会触发两次 PRESS**。PC 端在开麦/关麦的切换窗口（约几百毫秒）内有
防抖（`apm_app::core` 的 `Inner::stream_starting` 占位），窗口内的双击只算一次动作；
窗口外的双击仍是一次正常的开+关。三键方案的语义代价还在——真需要双击时再单独加事件，
别指望 toggle 兼容它。

## 界面怎么摆（G5）

界面上按**角色**分三块，与 `bindings` / `hooks` 的存储结构不是一一对应（分区只是展示）：

| 界面区块 | 内容 | 落盘位置 |
| --- | --- | --- |
| 麦克风 | 「开麦键」下拉（`up`/`down`/`ok` 三选一）+「开麦方式」（hold 未实现，置灰占位） | 被选中那一个写 `{"key":"ptt-toggle"}` 进 `bindings` |
| 快捷键映射 | **除开麦键之外**的两个按键：修饰键 + 目标键 + 连发次数 | `bindings` |
| 采集时注入 | `capture.start` / `capture.stop` 的快捷键 | `hooks` |

开麦键那一个在界面上不出现"目标键"输入框，也没有连发次数——它没有键名可填，
`repeat` 对 toggle 也没有意义。
