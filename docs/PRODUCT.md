# 产品定义：AI Passport Mic

## 一句话目标

让 AI Passport 在 PC 上表现得像一个可靠的无线麦克风，同时允许用户把设备按键映射成自己常用的快捷键。

## 用户场景

1. 用户把设备插上 USB。新设备（裸片）由软件自动写入固件；已经有固件的设备跳过这一步。
2. 用户在系统蓝牙设置中配对 AI Passport。首次配对是系统弹窗，软件只能引导，不能代劳。
3. PC 软件连接设备，并把解码后的音频持续写入虚拟声卡。
4. 会议、录音或直播软件选择虚拟声卡作为麦克风。
5. 用户按一下 OK 开麦、再按一下关麦；UP / DOWN 可执行用户配置的快捷键。
6. 用户运行录音测试，得到可比较的音质报告。

## 开箱体验（第一版按裸片出货）

设备出厂**不预烧固件**，客户拿到的是裸片。软件必须独立完成「识别 → 首烧 → 校验 → 交付」，
用户不需要装 ESP-IDF、不需要开终端、不需要按键进下载模式。

之所以能这样：ESP32-C3 的 USB-Serial-JTAG 是**芯片内置**的（不是 CH340/CP2102 这类外置串口
芯片），macOS/Linux 原生识别为 CDC-ACM，Windows 10+ 走系统自带 usbser，三者都不需要装驱动；
ROM bootloader 固化在芯片里，esptool 走 USB 控制线软复位即可进入下载模式，不用按 BOOT 键。

| 步骤 | 软件行为 | 失败时 |
| --- | --- | --- |
| 1. 识别 | 按 USB VID `0x303A` / PID `0x1001` 找设备，再确认是 ESP32-C3 | 提示未检测到设备，给接线与换线指引 |
| 2. 判定 | 读 flash `0x10020` 处的 app 描述符取版本；整片 `0xFF` 判为空片 | 读失败按"未知"处理，转强制烧写 |
| 3. 烧写 | 写 bootloader `0x0` / 分区表 `0x8000` / app `0x10000` 三段 | 保留可重试状态，重插后继续 |
| 4. 校验 | 回读 app 分区算 MD5（设备侧 `FlashMd5` 与本地同名算法比对），不一致不宣告成功 | 不宣告成功，提示重试而不是"已完成" |
| 5. 收尾 | 复位设备，等 BLE 广播，进入配对引导 | —— |

硬约束：

- **NVS 不擦。** 按键映射与蓝牙配对信息在 `0x9000`，烧写只覆盖上面三段。重新烧写不等于
  恢复出厂设置；要清配置必须是用户显式点的独立操作。
- **烧写不改变硬件的不可恢复状态。** ROM bootloader 在芯片内，烧写中断的设备仍能再次进入
  下载模式，不存在"刷坏就报废"。
- **不承诺零点击。** 蓝牙配对弹窗、辅助功能授权、虚拟声卡安装是系统或第三方的事，
  软件只做检测与引导，不假装能代劳。
- **只动自己的设备。** 不枚举、不写入、不擦除其他串口设备；VID/PID 与芯片型号双重确认后
  才允许写 flash。

## 第一版需求

### 音频

- 设备端 16 kHz、16-bit、单声道采集。
- BLE 自定义 GATT 传输，块长 20 ms；允许 PC 端检测丢块和序号跳变。
- PC 端将连续 PCM 输出到用户选择的虚拟声卡（BlackHole / VB-CABLE）。
- 支持同时保存 WAV，便于复现音质问题。
- 连接中断、音频未订阅、虚拟声卡不可用时必须有明确状态，不能静默假装在录音。

### 按键

- **一个键一个动作**：UP / DOWN / OK 各一条映射（`keymap-4`）。按下即触发，
  抬起 / 短按 / 双击 / 长按都不参与映射。固件仍会上报 5 种手势码（跨端协议不动）。
- OK 是**开关式**：按一下开麦、再按一下关麦。代价是没有"松手自动停"，
  必须配超时兜底与显眼的"正在采集"指示。
- **采集钩子**：开麦 / 关麦的那一刻可配置自动注入一个快捷键（点按），
  需要辅助功能权限；注入失败不影响开麦。
- 注入层（M3）已实现 macOS 点按注入与设备按键直连（OK 开关采集、up/down 注入映射键）；
  **真机端到端已验证（2026-11-06）**。"按住不放"模式尚未做；
  **关麦兜底已实现**（连续采集 N 分钟自动停，默认 10、可配 1–1440，见 [`GUI_IMPLEMENTATION_LOG.md`](GUI_IMPLEMENTATION_LOG.md) §14.19）。
- 每个事件可映射到一个主键和 Ctrl / Shift / Alt / Win 修饰键组合。
- 映射可保存、恢复默认、导入和导出 JSON。
- OK 的按下/抬起默认承担 PTT；若用户改写，必须保留可靠的停止采集方式。
- 注入快捷键时，无论成功或异常，都必须释放所有按下的修饰键。

### 音质

- 提供客观指标：时长、RMS、峰值、削波比例、直流偏置、过零率。
- 提供链路指标：丢块/序号跳变、启动延迟、稳态延迟、连续录音稳定性。
- 提供固定测试矩阵和 1–5 分主观评分。
- 报告必须区分“软件分析通过”和“真机听感通过”。

## 非目标

- 第一版不做系统音频驱动，也不做 HFP 麦克风 —— 后者是 ESP32-C3 的硬件限制（只有 BLE，
  没有经典蓝牙），不是"以后再做"。用户需要自备虚拟声卡（见
  [`ARCHITECTURE.md`](ARCHITECTURE.md) 的「分发与安装成本」）。
- 第一版不做 ASR、文字注入、AI Agent 或云端服务。
- 不承诺在没有测试仪器、声学和硬件记录时给出“音质合格”结论。
- 不修改系统蓝牙配对设置。首次配对、辅助功能授权都是系统弹窗，软件只做检测与引导，
  不伪装成"一键完成"。
- 不擦除 NVS 里用户攒下的配置（按键映射、配对别名）。烧写只覆盖 bootloader / 分区表 / app
  三段；"恢复出厂设置"必须是用户显式点的独立操作。
- 不烧写、不擦除、不枚举其他串口设备。只处理 VID `0x303A` / PID `0x1001` 且芯片型号确认为
  ESP32-C3 的目标。

## 验收口径

分两段，不要混在一起谈。

**初始化阶段（当前，已完成）**

- 新机器能按 `docs/ENVIRONMENT.md` 安装并激活 ESP-IDF 5.5.3。
- `./scripts/verify.sh` 通过：目录结构、文档内链、脚本权限、环境快照。
- 按键映射 schema 与音质报告格式有可读样例与字段说明。
- 仓库里不包含任何上游项目的整份拷贝。

**功能阶段（M1 起）**

- 固件能生成可校验的合并镜像，且烧录后按键与 PTT 在真机上可用。
- 裸片插上后，软件能在没有 ESP-IDF、没有终端的情况下完成烧写并通过回读校验；
  烧写中断的设备重插后能继续，不需要返厂。
- 重新烧写不清空 NVS：烧写前后蓝牙配对与按键映射保持不变。
- PC 端能把 PCM 稳定写入虚拟声卡，断连/未订阅/声卡缺失都有明确状态。
- 音质报告能区分「软件分析通过」和「真机听感通过」。
- 没有硬件证据时不得标记通过。
